# CeliTrip 0.3.0 — draft development checkpoint notes

**Historical checkpoint draft.** Superseded by the [final prerelease notes](v0.3.0.md). Statements below describe checkpoint preparation, not the current publication state; consult [VERSION.json](../../VERSION.json). Do not use this draft as `--notes-file`.

**Unreleased.** These are local draft notes, not an existing GitHub release or publication announcement. No tag, release date, deployment or production readiness is claimed.

This checkpoint groups the working local Milestone 2 capabilities while preserving the accepted blue design and persisted Hebrew/English/French/Russian Rome journey:

* Authenticated editorial management with operator-created accounts, disabled public signup, PostgreSQL sessions, mandatory MFA by default, scoped roles, recovery and revocation. The explicit password-only owner demo exception remains restricted to its single account, guarded fictional environment and loopback access, without fabricating MFA state.
* Immutable content/evidence/translation revisions, exact-revision review, private previews, atomic publication, withdrawal and audited private corrections. Substantive content retains subject review and all four language gates.
* A responsive administration workspace: database-backed dashboard, destinations/places/categories, sources/evidence, translations, review/publication, corrections, protected team/access controls, consumed localized settings and audit history.
* Source-language-first geographic naming with **working Wikidata lookup**, country/city identity and hierarchy, editable protected names, provenance and stale-response checks. **DeepL configuration and live verification remain deferred; general machine translation is not operational.**
* Simplified basic-geography publication with explicit publisher confirmation, separate drafts/published revisions, optional private notes, reasoned withdrawal/archive, contextual navigation, saved overview and action-local errors/focus. This cannot publish attached unreviewed guidance or claims.

The owner reviewed the corrected destination experience and said it “looks good.” This records acceptance of that demonstrated local workflow only, not every administration flow, real content, human translations, medical/card wording, reviewer appointments or production readiness.

**Local API breaking changes:** destination writes require the exact expected revision/version; publication requires `confirmGeography: true`; publication/archival cannot be performed through a status dropdown. Existing public Rome routes remain compatible. Use additive migrations and existing local data; do not reset/reseed the owner database.

Validation reuses the completed 41-test PostgreSQL suite, isolated HTTP authorization/publication checks, and documented four-language administration/HE-EN destination browser evidence. This checkpoint adds focused version/history checks and refreshed application/prototype label checks; it does not claim every workflow was retested. See [checkpoint validation](../technical/CHECKPOINT_0.3.0_VALIDATION.md).
