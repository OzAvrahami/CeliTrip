# CeliTrip v0.3.0 — Milestone 2 development prerelease

This development prerelease groups local editorial management, a four-language administration workspace and the corrected destination workflow. It preserves the accepted blue design and PostgreSQL-backed Hebrew/English/French/Russian Rome journey. It is not a stable release or production deployment.

## Implemented

* Operator-created editorial accounts, disabled public signup, PostgreSQL sessions, default mandatory MFA, scoped roles, recovery and session revocation. The opt-in password-only owner-demo exception is confined to one account, loopback access and the guarded fictional environment; it does not fabricate MFA verification.
* Immutable content, claim, source and translation revisions; exact-revision reviews, private previews, atomic local publication, withdrawal and audited corrections. Substantive content retains subject review and all four language-review gates. Public pages remain pinned to published revisions.
* Eight administration sections: dashboard, destinations/places, sources/evidence, translations, review/publication, corrections, team/access, and settings/activity. These include searchable lists and database-backed work queues, category management, protected team controls and consumed localized settings.
* Source-language-first destination names with working identity-based Wikidata geographic lookup, country/city relationships, protected manual corrections, provenance and stale-response rejection.
* Simplified geography-only publication with explicit publisher confirmation, separate draft/published revisions, optional private notes, action-specific reasons, contextual back navigation, saved overviews and actionable local feedback. Geographic publication cannot publish attached unreviewed guidance or claims.

## Compatibility and validation

**Breaking changes for local administration callers:** destination writes require the exact expected revision/version; geographic publication requires `confirmGeography: true`; publication/archival use explicit actions rather than a status dropdown. Apply additive migrations without resetting or reseeding existing data. Existing public Rome URLs remain compatible.

Validation includes the documented 41-test isolated PostgreSQL suite, focused HTTP authorization/publication checks, four-language administration and Hebrew/English desktop/mobile destination evidence, plus version/history checks. Unchanged application/browser evidence was reused for release preparation; no full workflow rerun is implied. See [geography validation](https://github.com/OzAvrahami/CeliTrip/blob/v0.3.0/docs/technical/GEOGRAPHY_USABILITY_VALIDATION.md) and [release-preparation checks](https://github.com/OzAvrahami/CeliTrip/blob/v0.3.0/docs/technical/RELEASE_0.3.0_VALIDATION.md).

The owner accepted the demonstrated corrected destination-management workflow (“looks good”). This does not extend acceptance to every administration flow, real content, translations, medical/card wording, reviewer authority or production readiness.

## Remaining limits

* Content publication and synthetic reviews remain restricted to local fictional data. Real reviewer assignments, venue evidence, launch coverage and publication policies remain pending; proposed review intervals are inactive.
* **DeepL configuration and live verification remain deferred. General machine translation is not operational.** Geographic-name lookup and editable localized names do not constitute human translation approval.
* Hotels, travel hubs, maps, cards/offline and later cloud capabilities remain prototype demonstrations or future implementation work. No deployment or cloud provisioning is included.

The historical v0.2.0 prerelease and its immutable tag target are preserved. For local setup, use the [development guide](https://github.com/OzAvrahami/CeliTrip/blob/v0.3.0/docs/development/LOCAL_DEVELOPMENT.md).
